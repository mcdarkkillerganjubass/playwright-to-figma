# Native mockup fidelity review

Reviewed 2026-11-23. Scope: read-only comparison of the existing mockup, its saved browser screenshot/capture, current Figma node properties and a reproduction of the source checkpoint in an isolated checkout. No converter code or Figma layers were changed. Primary-source API research is in [dom-to-figma-fidelity-sources.md](dom-to-figma-fidelity-sources.md).

## Verdict

The current PoC demonstrates editable construction and retained node identity. It does **not** satisfy faithful screenshot reproduction. Several differences are avoidable conversion errors, independently of the deliberately approved fallback font. Passing the current tests is not evidence of visual fidelity.

## Observed defects and causes

## Reproduction and signal

Private screenshot/DOM evidence and probe scripts are retained outside the shared repository under `/private/tmp/figma-native-trial/`. The comparison pairs are dimension-aligned 1440×1000 images at one CSS-pixel scale. A temporary standard-library PNG comparison script was run and returned a failing diagnostic signal before root-cause conclusions.

For the current reviewed Figma render, the fraction of pixels with any RGB-channel delta greater than 16/255 is 14.63% in the center-button crop, 7.54% in the sidebar crop, 5.89% in the history crop and 3.38% in the floating-label crop. Whole-screen difference is only 2.13%, diluted by large blank areas. These figures describe these selected crops; they are not universal similarity scores. The temporary 2%-per-region gate is a diagnostic aid, not an approved publication tolerance. Antialiasing, fallback fonts and missing geometry all contribute to pixel differences.

The original tests assert export presence, string values, clipping flags, SVG markup, unchanged source PNGs and safe ID reconciliation with a builder harness. They do not render Figma and compare its output with the browser. `publication.py` compares new source captures to a previously published source baseline; it does not test conversion fidelity. Those checks should continue, with a separate visual gate.

## Browser-data experiment

A pinned local Chromium reproduction returned 34 pseudo nodes and 46 text boxes through DOMSnapshot.captureSnapshot. It also reported actual rendered fonts through CSS.getPlatformFontsForNode. This is promising input for a richer adapter; it is not a finished converter or a full browser paint-command stream. [Official DOMSnapshot schema](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/DOMSnapshot.pdl), [CSS schema](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/CSS.pdl).

Importantly, the native input value had no descendant text box in that snapshot. A separate DOM.describeNode query with pierce:true exposed its user-agent shadow-root editor and text node; DOM.getBoxModel and DOM.getContentQuads on their backend IDs returned the actual text box described above. This was exercised successfully on this browser/control; do not assume universal support across controls, browsers or protocol versions. [Official DOM domain](https://chromedevtools.github.io/devtools-protocol/tot/DOM/).

## Recommended implementation sequence

1. **Make the failure visible to the workflow.** Keep the current source capture, and export Figma renders for a fixed regression fixture set. Compare meaningful UI regions, geometry and text baselines; fail missing icons/outlines, clipping and overlapping text. Separate antialiasing tolerance from layout errors. Reject material unsupported features in strict mode instead of publishing with warnings alone.
2. **Fix the demonstrated defects first.** Add native-control text measurement/adapters; convert narrow inset outlines to strokes; preserve pseudo icons. Each gets a failing visual regression from the actual component pattern before implementation. Avoid a general rendering-engine rewrite as the first step.
3. **Preserve typography styles with family fallback.** Record browser font aliases, actual PostScript/family evidence, fallback runs, weight/axes, size, spacing and line metrics. Prefer the original available family; otherwise select a deterministic available fallback. Apply the source font size, actual computed line-height, weight, italic style, letter spacing, alignment, decoration and text transformation to that family. Match the requested weight through an available style or supported variable-font axis; report any further style approximation. Do not replace the source line-height with a Range rectangle height or reset typography to fallback defaults. Preserve source container geometry and line breaks, then measure resulting line widths/baselines after import. Arbitrarily narrowing text boxes or replacing all text with autosized lines is not a font-matching solution. [Figma font loading](https://developers.figma.com/docs/plugins/api/properties/figma-loadfontasync/), [text resizing](https://developers.figma.com/docs/plugins/api/properties/TextNode-textautoresize/).
4. **Introduce a versioned observation layer.** For Chromium, collect DOMSnapshot plus targeted DOM/CSS queries and assets. Keep semantic identity/DOM ancestry separate from the rendering hierarchy: browser paint order and clipping are not simply DOM nesting. Store measured fragments, local geometry, accumulated transforms, content/border boxes, clips, paints and source references. Keep the portable browser-evaluate adapter explicitly lower-coverage until it passes the same fixtures.
5. **Expand supported paints and assets deliberately.** Bundle actual image bytes and crops, preserve simple gradients, normalize SVG dependencies and mask behavior, and model stacking contexts. Build a feature matrix: exact within validated tolerance, explicitly approximate, or unsupported. Auto Layout inference and component substitution should follow visual correctness; matching design tokens alone does not repair measured geometry.
6. **Gate publication and baseline advancement.** Require visual checks and editability/identity checks independently. Record a new publication only after both pass. Re-run the reviewed source state after every relevant renderer change. Retain the existing skill and connected Figma integration; these improvements do not require a custom plugin or AI-based visual reconstruction.

## Precision target

For a supported component set with exact available fonts and assets, close deterministic native reproduction is a reasonable engineering target. Define explicit per-feature tolerances using observed cross-renderer variation; do not promise identical raw pixels across arbitrary Chromium and Figma rendering.

If the original font is unavailable, fully editable text cannot simultaneously retain that different font and exactly reproduce the original glyphs. Outlining text changes editing semantics. A raster fallback preserves pixels only for that region and must be reported, not disguised as native editable content. Accepted policy: keep text editable and allow font-family substitution while preserving source typography styles. Glyph shape and advance-width differences attributable to that substitution are expected; input misplacement, lost line-height, clipping and overlapping text still require correction. Other materially unsupported rendering cases should fail explicitly. This is a rendering-model constraint, not a reason to accept the current avoidable input, outline and icon errors.
