# DOM → editable Figma: fidelity evidence

Researched 2026-11-23. Scope: improve this repository's checkpoint capture and native renderer; no new plugin, production changes, or converter benchmark. Read `assets/design-capture.ts`, `assets/design-renderer.mjs`, and `html-to-figma-reference.md`. External links below are primary sources. Proposals are explicitly marked; documentation establishes available data, not visual parity.

## Verified capture options

Chromium's experimental `DOMSnapshot.captureSnapshot` returns flattened DOM (including shadow DOM), requested computed styles, layout bounds and post-layout text boxes. It exposes pseudo types, current input/textarea values, checked/selected state, and selected image URLs. `includeDOMRects` adds offset/client/scroll rectangles; `includePaintOrder` adds paint indices alongside stacking-context markers. Paint indices can tie. Text boxes identify layout substrings using UTF-16 offsets; the schema explicitly warns that their layout can change between versions. The deprecated method is `getSnapshot`; there is no current `getLayoutTreeAndStyles` command in this domain. Neither method's response is a complete drawing-command stream or an asset bundle. [Official protocol schema](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/DOMSnapshot.pdl)

Playwright exposes `browserContext.newCDPSession(pageOrFrame)` only for Chromium. **Proposal:** add an optional, versioned Chromium capture adapter rather than silently making the browser-side `page.evaluate` helper depend on CDP. Pin and record browser/protocol versions; probe pseudo nodes, iframe targets and coordinate spaces in real fixtures before adopting it. CDP's documented inclusion of iframes is not evidence that every out-of-process frame appears correctly from one attached target in this project's setup. [Playwright API](https://playwright.dev/docs/api/class-browsercontext#browser-context-new-cdp-session)

## Verified fidelity constraints and project implications

| Area | Primary-source fact | Current source / proposed improvement |
| --- | --- | --- |
| Text measurement | Range rectangles use font ascent/descent and advance widths; they are not glyph-ink bounds. Partial grapheme/surrogate selections include the full typographic character unit. Ancestor transforms apply. [CSSOM View §9](https://drafts.csswg.org/cssom-view/#extensions-to-the-range-interface) | The comment “measured glyph bounds avoid reflow” overstates `textNode`. It iterates UTF-16 units and groups solely by top coordinate. **Proposal:** preserve rendered fragments/runs and original logical text; test ligatures, combining marks, bidi, inline styles and collapsed whitespace. |
| Fonts actually used | `CSS.getPlatformFontsForNode` reports fonts used for child text, including family, PostScript name, custom-font flag and glyph counts. It does not return per-glyph font assignments. [CSS schema](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/CSS.pdl) | First declared `font-family` is not necessarily the rendered font. **Proposal:** record actual font evidence, declared fallback chain, letter/word spacing, line-height, stretch, variation/feature settings and direction. Report unresolved fallback runs. |
| Figma fonts | Text rendering changes require loaded fonts. `loadFontAsync` only accesses editor-available fonts, not arbitrary downloaded webfonts. Current docs support variable-font `variationSettings`, e.g. `wght: 550`. [loadFontAsync](https://developers.figma.com/docs/plugins/api/properties/figma-loadfontasync/) | The renderer's Regular/Bold threshold and italic branch lose intermediate weights and bold italic; these are project shortcuts. **Accepted direction:** prefer the original family and use a recorded fallback family when it is unavailable. Preserve source size, line-height, weight/axes, italic style and spacing on the fallback; report any additional style approximation. Verify the actual connected executor supports these current API fields. |
| Text layout | Figma supports range styling, letter spacing, line height and explicit text resizing modes. [TextNode](https://developers.figma.com/docs/plugins/api/TextNode/) | `WIDTH_AND_HEIGHT` lets Figma recompute width; assigning Range height as line-height does not establish the original baseline. **Proposal:** compare exported line positions/widths and calibrate vertical placement using real font fixtures. One text node per line preserves editability but loses paragraph reflow semantics. |
| Paint order | CSS painting includes backgrounds/borders, negative stacking contexts, in-flow blocks, floats, inline text, positioned descendants and outlines; pseudo-elements participate. [CSS 2.2 Appendix E](https://www.w3.org/TR/CSS22/zindex.html) | Sorting each parent's children by numeric `z-index` is insufficient. **Proposal:** capture stacking/paint evidence and build rendering groups with deterministic tie handling; preserve identity separately from DOM nesting. Do not assume sorting the whole tree by CDP paint index solves every paint phase. |
| Transforms | Transform matrices accumulate through ancestors and around transform origins; client rectangles reflect transforms. [CSS Transforms §3](https://www.w3.org/TR/css-transforms-1/#transform-rendering) | Axis-aligned bounds discard rotation/skew; subtracting parent viewport x/y cannot reconstruct transformed local coordinates. **Proposal:** preserve local geometry and accumulated affine matrices, then test Figma transform mapping. Perspective/3D remains a separate unsupported class until verified. |
| Masks | CSS masks affect the element and descendants through alpha/luminance compositing; sizing, origin, position, repeat and multiple-mask composition matter. [CSS Masking](https://www.w3.org/TR/css-masking-1/) | Recoloring an SVG to `backgroundColor`, stretching it to bounds and returning before children is faithful only to a narrow icon case. **Proposal:** identify that case explicitly; otherwise preserve mask geometry/composition or report unsupported output. |
| Native controls | HTML rendering guidance permits native appearance and platform-dependent widgets; ordinary author boxes are not the complete control appearance. [HTML rendering / widgets](https://html.spec.whatwg.org/multipage/rendering.html#widgets) | Capture `.value`, `.checked`, selected options and placeholder styles separately. CDP form properties do not reconstruct native checkmarks, arrows, focus rings or date controls. **Proposal:** fixture-specific native shape adapters, verified against the pinned OS/browser. |

## Pseudo-elements, SVG and assets

**Proposal:** use measured pseudo layout nodes and rendered content instead of guessing `::before`/`::after` positions from owner padding and parsed width/height. Current capture drops generated text and most non-absolute pseudos. Preserve each pseudo's identity, styles, transforms and paint relationship; validate counters, icon fonts and wrapped generated content independently. CDP provides relevant pseudo/layout data, but the complete adapter remains unimplemented.

Figma's official typings define `createNodeFromSvg(svg): FrameNode` as equivalent to the editor's SVG import. This is an import capability, not a promise of full browser SVG/CSS support. Current capture inlines only fill, stroke, stroke-width and opacity; external references, inherited styles, filters and `<use>` dependencies need deliberate handling and representative import tests. The renderer deliberately rejects `<image>`, `foreignObject` and external hrefs. **Proposal:** normalize supported SVGs with dependencies resolved and report unsupported features before writing. [Official Figma typings](https://raw.githubusercontent.com/figma/plugin-typings/master/plugin-api.d.ts)

Image geometry needs `object-fit` and `object-position`, not just the `<img>` border box. [CSS Images §4](https://www.w3.org/TR/css-images-3/#sizing)

Figma accepts encoded image bytes into image resources used by shape fills; documented `createImage` formats are PNG/JPEG/GIF, with 4096-pixel dimension limits. **Proposal:** bundle content-addressed selected assets in the authenticated capture session, normalize unsupported encodings, record crop/placement and background layer ordering, and keep editable image-filled rectangles. An image fill is an editable image layer, not editable source pixels. Current capture merely warns for images/background images and the schema has no image kind. [Figma createImage](https://developers.figma.com/docs/plugins/api/properties/figma-createimage/)

## Recommended next experiment, not established results

1. Separate source observations from conversion policy in a versioned intermediate representation: stable keys, source node/pseudo references, fragments, local geometry, transforms, stacking/clips, typography, paints and asset hashes.
2. Stabilize one checkpoint and capture its PNG plus observations under the same font/animation/scroll state. Build a supported-feature matrix and preserve explicit unsupported diagnostics.
3. First validate source typography styles on original or accepted fallback fonts, pseudo icons, control text baselines, image placement and overlay stacking in the project's actual representative page. Then add isolated transform, mask, shadow, gradient, RTL and SVG fixtures as needed.
4. Export the resulting Figma render and measure differences by feature/region, alongside native text/vector/image counts and substitution reports. A screenshot match alone does not establish editability; editable nodes alone do not establish screenshot fidelity.

**Engineering conclusion:** better observations can eliminate many current avoidable errors. No reviewed primary source promises arbitrary browser CSS/SVG/native-control output can remain entirely native editable Figma content with identical pixels. Canvas/WebGL/video state and arbitrary filter/compositing effects require a declared approximation, explicit unsupported result, or a raster region. Text converted to vector outlines retains editable paths but loses editable characters. If all text/objects must retain their original editing semantics, unsupported cases must be reported rather than hidden behind a pixel-perfect claim. This conclusion is an inference from the different rendering models and API boundaries, not a benchmark or a proof that a specific page cannot match closely.
