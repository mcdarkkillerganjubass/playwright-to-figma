# Publication rules and recovery

Project instructions own destination and grouping. A minimal block may specify a Figma Design URL and overrides such as “pages by product area, sections by scenario; branch in section details.” No Figma URL, private repository identity or local publication history belongs in the shared skill repository.

Comparison identity includes canonical project root, Figma file key, grouping scope and stable scenario ID. The `--layout` key defaults to `branch-page/horizontal-v1`; set a different stable key when the project's layout differs or its generation policy changes. Pass identical arguments to inspect and record. Layout and target changes invalidate comparison intentionally. Never save tokens in the state directory.

First publication: inspect successful export, resolve/create the intended page, create section, upload screenshots, create anchors and connector copies, verify, then record the baseline. The script returns `changed: true` when no baseline exists.

Unchanged: check the actual mapped page/section still exist. If present, do not re-upload images or write to Figma. If absent, regenerate and update IDs. The fingerprint does not check manual edits made in Figma; generated content is owned by the publisher under the project's replacement policy.

Changed: update the existing section in place. Keep section, frame, image layer, trigger and connector IDs. Upload new images as fills on the existing image nodes, adjust bounds and connector properties, and resize the existing section. Preserve its position and existing comment threads. Comments can be pinned to descendant layers, so preserving the outer section alone is insufficient. Verify node identity before and after mutation.

Use stable semantic state/transition identifiers. An ordinal such as state-2 is not sufficient evidence of identity after inserting a new state. The bundled prototype exporter does not yet provide explicit semantic state IDs: require an explicit verified mapping or extend the exporter before a structural refresh. Store the mapping with the local publication state; the current CLI records page/section IDs only, so additional object mapping must be persisted deliberately rather than assumed to exist.

New states get new nodes. Removed states/edges retain their existing objects in a visible Archive area inside the same section, with clear names and retained attachments. Enlarge the section as needed. Do not remove or resolve comment threads, or synthesize replacement comments. Removing archived objects requires separate explicit authorization. Comment pins retain their node-relative offsets; a changed UI can make a preserved pin refer to an outdated visual location. Report this limitation rather than claiming semantic pin migration. Canvas-coordinate comments also cannot be assumed to follow a rearranged screen.

Preload and validate assets, snapshot affected node properties/image hashes, then mutate the verified nodes. Tool calls may partially apply changes. Inspect before retrying, restore prior properties where possible, retain old images for recovery and report any remaining partial state. Record a new baseline only after a verified successful refresh. Serial publication is supported; coordinate another publisher instead of racing it. Keeping comment anchors is an execution requirement, not a guarantee already tested with live threads in every integration.

Comparison uses exact SHA-256 fingerprints first, then decoded pixel comparison only when the separate metadata fingerprint matches. The shared default noise budget is 10 differing pixels total across all scenario images, with RGB delta at most 1 per channel and exact alpha. Dimensions, labels, route paths, scroll, states, transitions and trigger bounds must match exactly. PNG compression or ancillary metadata may differ without a visual change. Dynamic text still counts as content: use fixed dates and fixture data.

`record` validates 8-bit non-interlaced RGB/RGBA browser PNGs, stores compressed RGBA blobs under `pixels/` in the local state directory, then atomically updates the publication record. Comparison never replaces those blobs or advances the baseline. This prevents incremental noise drift. Keep the pixel blobs with the JSON state when transferring local publication history. Missing pixel baselines fall back to exact comparison; corrupt baselines report an error. Old records remain compatible: enrich one only from the known published export whose exact fingerprint matches it, after verifying target IDs. Do not migrate by trusting a merely similar current export. Unsupported PNG formats must be recaptured as browser RGB/RGBA screenshots. The decoder validates chunk checksums and bounds decompression size.

Codex discovery normally uses a skill folder containing SKILL.md. Other agents may need a different installation location or wrapper. Python comparison and TypeScript export are portable; Figma connector capabilities must be checked for each integration. A Git repository distributes versions; it does not force updates on colleagues.
